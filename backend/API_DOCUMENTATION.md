# REST API Documentation

The full interactive API reference is auto-generated by FastAPI and always reflects the exact current code:

- **Swagger UI:** `http://localhost:8000/docs` (try endpoints directly - click "Authorize" and log in with the demo credentials first)
- **ReDoc:** `http://localhost:8000/redoc`
- **Raw OpenAPI schema:** `http://localhost:8000/openapi.json`

This document is a human-readable summary of the same API, organized by resource.

## Authentication

Every endpoint below except `/`, `/health`, and `/health/db` requires a JWT bearer token, obtained from:

```
POST /auth/login
Content-Type: application/x-www-form-urlencoded

username=demo_doctor&password=ChangeMe123!
```

Response: `{"access_token": "...", "token_type": "bearer"}`. Send it on every subsequent request as `Authorization: Bearer <token>`.

## Scans (Phases 5-8)

| Method | Path | Description |
|---|---|---|
| POST | `/scans` | Submit scan reports for an application. Runs the full pipeline (parse → store → predict → explain → recommend → deployment decision) in one call and returns everything. |
| GET | `/scans` | Scan history. Optional `?application_name=` filter, `?skip=` / `?limit=` pagination. |
| GET | `/scans/{scan_uuid}` | Scan summary + computed features. |
| GET | `/scans/{scan_uuid}/findings` | The scan's individual vulnerability/issue findings. |
| GET | `/scans/{scan_uuid}/prediction` | The stored ML risk prediction. |
| POST | `/scans/{scan_uuid}/predict` | Re-runs prediction + explanation + recommendations + deployment decision for an already-stored scan (e.g. after retraining the model) and returns the updated results. |
| GET | `/scans/{scan_uuid}/explanation` | The stored Explainable AI breakdown (SHAP or rule-based, depending on which predictor ran). |
| GET | `/scans/{scan_uuid}/recommendations` | The stored, finding-linked remediation recommendations. |
| GET | `/scans/{scan_uuid}/deployment-decision` | The stored deployment decision for this scan. |

### POST /scans request body

```json
{
  "app_name": "healthsec-demo",
  "repository_url": "https://github.com/example/healthsec-demo",
  "commit_sha": "abc1234",
  "trivy_report": { "...": "raw Trivy JSON report, or omit if unavailable" },
  "dependency_check_report": { "...": "raw OWASP Dependency-Check JSON report, or omit" },
  "sonarqube_report": { "...": "output of scripts/fetch_sonarqube_report.py, or omit" }
}
```

`app_name` is required (non-blank). Every report field is optional - an omitted report is recorded as that scanner's status being `"missing"`, which the deployment policy treats as a failed mandatory check (see below), never as "no vulnerabilities found."

### POST /scans response body (also returned by POST /scans/{scan_uuid}/predict)

```json
{
  "scan": { "id": 1, "scan_uuid": "...", "commit_sha": "...", "scanner_status": {"trivy": "ok", ...}, ... },
  "features": { "critical_count": 2, "high_count": 3, "max_cvss_score": 7.5, "security_rating": "F", ... },
  "findings": [ { "source": "trivy", "identifier": "CVE-...", "normalized_severity": "CRITICAL", ... } ],
  "prediction": { "risk_category": "High", "predicted_probability": 0.78, "risk_score": 100.0, "model_used": "random_forest" },
  "explanation": { "method": "shap_tree_explainer", "contributions": [...], "summary": "..." },
  "recommendations": { "recommendations": [...], "summary": {"critical_count": 2, "high_count": 3, ...} },
  "deployment_decision": { "decision": "blocked", "reason": "...", "mandatory_checks_passed": true, "failed_checks": [] }
}
```

## Error Responses

All endpoints use standard HTTP status codes:

- `401 Unauthorized` - missing or invalid bearer token
- `404 Not Found` - the scan/application/resource doesn't exist, or hasn't had a prediction generated yet
- `422 Unprocessable Entity` - request body failed validation (e.g. blank `app_name`, a report field that isn't a JSON object)

Error bodies follow FastAPI's standard shape: `{"detail": "human-readable message"}`.
